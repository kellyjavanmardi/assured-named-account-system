Account-Brief Generator

A system that turns one dashboard click into a grounded, pre-meeting brief and next-best-action for the account owner — on demand, not a chat window.

↳
How this connects to Part 1's dashboard: the "Generate Brief" button on any account is this system's front door — it fires on exactly the account you're looking at, using the same Momentum Signal field the dashboard already shows as "why now." Same query, same source of truth, one click apart. Part 2 is this system's build_prompt() function, opened up and run live for whichever account the panel picks.
Focus
One agent, adaptive next-best-action — not three separate agents
Pulls an account's row, its top contacts, and its recent signals, and drafts a tight pre-meeting brief with a recommended next-best-action. The action itself adapts to context: book-a-meeting for a high-intent no-touch account, a build-vs-buy objection play when a CAIO risk is flagged, a save play if a pilot is asked to be treated as cooling. One prompt template, one output contract — not three separate agents to maintain.

Inputs & Output Contract

Inputs (per account)

  • Account row — tier, intent + trend, buying/deal stage, pilot status, pipeline, momentum note (warehouse table, 6sense-fed)
  • Top contacts — up to 3, ranked by seniority then engagement (Clay-enriched)
  • Recent signals — last 45 days, ranked by strength + recency (influ2 / HockeyStack / 6sense / Clay)
  • Quality flags — computed by the gate step, e.g. caio_roster_stale, dormant_60d
  • Constraint (optional) — champion_arming / save_play / expansion_push, the live-curveball lever

Output contract

{
  "account": string,
  "situation_summary": string,
  "key_signals": [
    { "date", "type", "detail" }
  ], // must trace to input
  "risk_or_opportunity": string,
  "next_best_action": {
    "action", "rationale"
  },
  "confidence": "high"|"medium"|"low",
  "data_gaps": [string]
}
Guardrails
Two layers — a system-prompt instruction the model follows, and code that checks it after the fact
Not grounded
System prompt: never invent a signal, date, contact, or number. Enforced twice — once as an instruction, once by validate_grounding() checking every cited signal against the real input after generation.
Carrier compliance
No coverage, liability, or claims-outcome determinations. No promised ROI, timeline, or regulatory outcome not present in the input — recommend, don't commit.
Cross-account leakage
Each brief is scoped to one carrier only — never reference another carrier's data, deals, or contacts when writing about this account.
Handling Bad or Missing Data
The gate runs before the model call — Claude never has to improvise on thin data
No contacts + no signals
Skip the Claude call entirely. Route straight to a human-review flag — never let the model guess its way to a plausible-sounding brief with nothing to ground it.
Days since touch > 60
Tagged dormant_Nd and passed explicitly into the prompt, so the brief says "going cold" instead of manufacturing urgency that isn't there.
CAIO signal predates contact record
Same staleness check as the dashboard — flagged as caio_roster_stale and surfaced in data_gaps rather than assumed resolved.
Product signal, no CRM pilot
Verified in the raw data: 7 of 30 accounts carry a "Pilot Milestone" signal while their CRM Pilot Status says None — product usage and CRM state have drifted apart. Flagged as pilot_signal_status_mismatch so the brief doesn't imply a pilot that isn't on record.
Model output fails grounding
One retry with a stricter reminder; a second failure routes to the human queue instead of delivering an ungrounded brief.
